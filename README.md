# 网页壁纸（WebWallpaper）

一个类似 [Plash](https://sindresorhus.com/plash) 的 macOS 小工具：把任意网页铺满桌面作为壁纸。窗口位于系统壁纸之上、桌面图标之下，默认不接收鼠标事件，所以桌面图标照常显示、照常点击和拖拽。需要临时操作网页时，可以按屏幕单独开启「浏览模式」，让该屏的网页像普通浏览器一样可交互。

面向本机自用：不启用沙盒、不做公证，使用 ad-hoc 签名。

## 功能一览

- 默认网址：所有未单独设置网址的屏幕共用
- 每块屏幕可单独设置网址，按显示器 UUID 持久化，重启、换屏、换位后仍对应正确的物理屏幕
- 每块屏幕可单独停用网页壁纸：停用后关闭该屏窗口、释放网页资源，露出系统壁纸
- 每块屏幕可单独开启 / 关闭浏览模式（可交互），同一时间可只有一块屏在浏览，也可多块各自独立开启；状态只在本次运行内有效，不写入配置
- 全部重新载入、手动暂停 / 恢复
- 屏幕休眠、锁屏时自动暂停，唤醒 / 解锁后自动恢复
- 网页权限设置：摄像头、麦克风、位置可按站点允许 / 拒绝 / 每次询问，并处理 macOS 系统层授权
- 未设置网址时显示一个离线时钟欢迎页；加载失败时显示错误页

明确不支持的能力：

- 网页通知（Web Notification / Web Push）：WKWebView 不提供宿主授权接口，网页的 `Notification.requestPermission()` 始终返回 `denied`，权限窗口里已注明，没有做开关
- 网页弹出新窗口：`window.open` 与 `target=_blank` 被忽略（浏览模式下也一样）
- 本地文件：只接受带主机名的 http / https 网址，`file://` 不可用

## 环境要求

- macOS 13 及以上
- Xcode 或 Command Line Tools（`xcode-select --install`）

## 构建与运行

从 GitHub 获取源码并启动：

```bash
git clone https://github.com/greatwoo01/WebWallpaper.git
cd WebWallpaper
./run.sh          # 构建并启动
```

只需要构建时，执行：

```bash
./build.sh        # 编译并打包成 build/WebWallpaper.app
```

也可以构建后双击 `build/WebWallpaper.app`，或在 `系统设置 → 通用 → 登录项` 里添加它实现开机自启。

`build.sh` 会生成 `Info.plist`（Bundle ID 为 `local.webwallpaper`，`LSUIElement` 让应用不显示 Dock 图标），写入摄像头、麦克风、位置的中文用途说明，并对 app 做 ad-hoc 签名。

首次打开若提示「无法验证开发者」，可执行：

```bash
xattr -dr com.apple.quarantine build/WebWallpaper.app
```

## 菜单栏使用

启动后菜单栏出现「照片」图标，应用不显示 Dock 图标。菜单每次打开时重建，屏幕列表、各屏当前网址和暂停状态都是实时的。

- **默认网址：…**：只读信息行，显示当前默认网址；未设置时显示「默认页面」
- **每块屏幕一行**：标题为「序号. 屏幕名称 — 当前网址」，停用的屏幕显示「已停用」，处于浏览模式的屏幕末尾会多出「（浏览模式）」。悬停展开子菜单：
  - **启用网页壁纸**：勾选状态即该屏是否启用；取消勾选会关闭该屏窗口并释放网页资源，露出系统壁纸
  - **浏览模式（可交互）**：勾选状态即该屏是否处于浏览模式；只影响这一块屏幕。停用的屏幕此项不可用
  - **当前：…**：只读，显示该屏实际使用的地址，或「已停用（显示系统壁纸）」
  - **设置此屏幕网址…**：只对该屏生效，输入框预填该屏已单独设置的网址；留空或取消则不修改。网址不带协议时自动补 `https://`
  - **使用默认网址**：清除该屏的独立网址，回落到默认网址（该屏没有独立网址时此项不可用）
- **设置默认网址…**：修改默认网址，只影响没有单独设置网址的屏幕；正在显示自定义网址的屏幕不变
- **全部重新载入**：按各屏当前网址重新加载所有已启用的屏幕，并解除手动暂停
- **暂停 / 恢复**：手动暂停时截图当前画面顶替网页，并停止加载、卸载页面内容；恢复后重新加载。手动暂停状态不写入配置，重启后不保留
- **退出浏览模式（Esc）**：只要有屏幕处于浏览模式，这一行就会出现，一次退出所有屏幕的浏览模式
- **网页权限…**：打开权限设置窗口（见下节）
- **退出**：结束应用

在「设置默认网址…」或「设置此屏幕网址…」里成功提交新网址时，会自动解除手动暂停。窗口里的输入框支持 Cmd+C / Cmd+V 和右键菜单。

## 浏览模式

浏览模式让某一块屏幕上的网页临时变成可交互状态，其它屏幕不受影响，仍是纯壁纸。

- **按屏幕独立切换**：在任意屏幕的子菜单里勾选「浏览模式（可交互）」只切换该屏；多块屏幕可以各自开启，也可以只开一块。每块屏的浏览状态按显示器 UUID 对应，拔插、换位不会串屏
- **交互能力**：该屏的网页可以点击链接、滚动、输入文字、右键、使用页面内的键盘操作，并会获得键盘焦点；同一时间只有获得焦点的屏幕接收键盘事件，点一下另一块浏览模式的屏幕即可切换焦点
- **窗口形态不变**：仍是铺满该屏、无标题栏、无边框的窗口，不会变成普通窗口；只是层级临时提高到普通窗口之上，避免被别的窗口压住
- **退出方式**：
  - 子菜单里取消勾选「浏览模式（可交互）」，只退出这一块屏幕
  - 菜单顶层的「退出浏览模式（Esc）」，退出所有屏幕；有屏幕处于浏览模式时这一项才出现
  - 键盘 Esc，等同于「退出所有屏幕的浏览模式」，是本应用收到该按键时执行
- **自动退出**：手动暂停、屏幕休眠、锁屏 / 切换用户、显示器布局或分辨率变化时，浏览模式会全部退出并回到纯壁纸
- **不跨重启**：浏览模式不写入配置，重启应用后所有屏幕都是纯壁纸；进入浏览模式时若处于手动暂停，会顺带解除手动暂停
- **代价**：处于浏览模式的屏幕会盖住该屏的桌面图标，直到退出；退出后恢复为可点穿图标的纯壁纸

## 网页权限

### 策略模型

权限按站点（域名）区分，三种能力：**摄像头**、**麦克风**、**位置**。

- 全局默认值：三行下拉框，可选「每次询问 / 允许 / 拒绝」，默认全部为「每次询问」
- 站点覆盖：每个站点每个权限可选「跟随默认 / 每次询问 / 允许 / 拒绝」；选择「跟随默认」即删除该站点的该项覆盖
- 站点列表自动包含默认网址和各屏网址所在的域，也可以点「添加站点…」预先添加（输入 `example.com` 或 `https://example.com`；带路径的裸地址无法识别）。站点行右侧的「−」会删除该站点的全部设置

策略解析顺序是站点覆盖优先，其次全局默认。网页请求权限时：

- 结果为「允许」：直接放行（摄像头 / 麦克风还会继续走 macOS 授权）
- 结果为「拒绝」：直接拒绝，网页会收到标准的拒绝错误
- 结果为「每次询问」：弹出「网页权限请求」面板，写明站点和请求的能力，可勾选「记住此站点的选择」（默认勾选）。勾选后把本次选择写入该站点的设置；不勾选则只对本次请求生效。关闭面板等同于拒绝

询问面板是非模态的，同一时刻只显示一个，后来的请求排队等待。面板显示期间应用会临时出现在 Dock 中，关闭后恢复；这是为了让面板在其他应用全屏时也能显示和点击。

### 三项能力的实现与表现

| 能力 | 处理方式 | 拒绝后的网页表现 |
| --- | --- | --- |
| 摄像头 | `WKUIDelegate` 的媒体授权回调，按站点策略决定 | `getUserMedia` 收到 `NotAllowedError` |
| 麦克风 | 同上；同时请求摄像头和麦克风时只弹一次面板，任一为「拒绝」则整体拒绝 | `getUserMedia` 收到 `NotAllowedError` |
| 位置 | 未使用 WebKit 自带定位（macOS 上没有公开的授权回调），而是注入脚本接管 `navigator.geolocation`，经原生 CoreLocation 取位置 | 回调收到错误 `code = 1`（PERMISSION_DENIED）；系统未授权时也按拒绝处理 |

位置的细节：只接管主页面，`iframe` 里的定位不经过本应用判断；`getCurrentPosition` 单次请求超时 20 秒；`watchPosition` 的订阅会在页面跳转、窗口卸载、暂停、停用屏幕时清理。定位精度固定为百米级，忽略网页传入的精度 / 超时参数。

### macOS 系统授权

摄像头、麦克风和位置的最终授权由 macOS 管理，应用层放行后还需要系统层同意：

1. 首次允许时，系统会弹窗询问，点「允许」
2. 如果之前点过「不允许」，网页之后只会一直得到拒绝结果；需要到 `系统设置 → 隐私与安全性 → 摄像头 / 麦克风 / 位置服务` 为本应用打开开关
3. 位置还需要在 `隐私与安全性 → 位置服务` 中勾选本应用，应用只申请「使用期间」授权
4. 权限窗口里的「打开系统隐私设置」按钮可直接跳转到隐私设置页

拒绝系统授权时，网页侧同样是标准的拒绝错误（`NotAllowedError` 或位置 `code = 1`），不会静默放行。

## 配置存储

所有配置都在 `UserDefaults`，域名为 `local.webwallpaper`（plist 位于 `~/Library/Preferences/local.webwallpaper.plist`）。

| 键 | 类型 | 说明 |
| --- | --- | --- |
| `WebWallpaper.currentURL` | String | 默认网址 |
| `WebWallpaper.screenURLs` | [String: String] | 每屏独立网址，键为显示器 UUID |
| `WebWallpaper.disabledScreenIDs` | [String] | 停用了网页壁纸的屏幕 UUID |
| `WebWallpaper.defaultPermissions` | [String: String] | 全局默认权限：`camera` / `microphone` / `location` → `ask` / `allow` / `deny` |
| `WebWallpaper.sitePermissions` | [String: [String: String]] | 站点覆盖：域名 → 权限 → 策略 |

屏幕身份优先取 `CGDisplayCreateUUIDFromDisplayID` 得到的显示器 UUID；极少数虚拟 / 串流显示器拿不到 UUID 时，退化为「名称 + 分辨率」作为键。

查看与重置：

```bash
defaults read local.webwallpaper
defaults delete local.webwallpaper            # 清空全部配置（含权限）
```

## 已知限制

- 默认纯壁纸模式下窗口不接收鼠标事件，网页不可点击；开启浏览模式后才可交互，且只对开启的屏幕生效
- 浏览模式窗口层级在普通窗口之上，会盖住该屏的桌面图标和其它窗口，直到退出；状态不写入配置，显示器布局变化或重启会回到纯壁纸
- 网页通知不支持（见上文），网页里的通知请求一律返回 `denied`
- 带声音的媒体不会自动播放，需要在浏览模式下点击后才能播放（WebKit 要求用户手势）；静音视频和动画可自动播放
- 会话被锁屏或屏幕休眠时会暂停并卸载网页；暂停期间只保留最后画面
- 显示器分辨率或排列变化时会重建全部壁纸窗口并重新加载
- 网页定位只在主页面生效，且精度固定、单次超时 20 秒
- 只支持 http / https 远程网页，不支持 `file://`
- 不启用沙盒、不公证；换机器拷贝 app 后可能需要去掉 quarantine 标记

## 常见问题

**点击桌面时网页壁纸消失？**

这是 macOS Sonoma 起的系统功能。到 `系统设置 → 桌面与程序坞 → 点按墙纸以显示桌面`，改为「仅在台前调度中」即可。

**网页请求摄像头 / 麦克风 / 位置时，系统弹窗显示的是终端或 IDE 的名字？**

从终端（或 IDE 的终端）启动 app 时，macOS 会把授权请求记到父进程名下，这是系统行为。把 app 从 Finder、Dock 或登录项打开，弹窗就会显示「网页壁纸」。如果已经误拒绝，请到系统设置里修改对应授权。

**权限窗口里明明设为「允许」，网页还是失败？**

先看系统层授权是否被拒绝：`系统设置 → 隐私与安全性` 中本应用的摄像头 / 麦克风 / 位置服务开关是否打开。应用层只是第一道，系统层拒绝时网页仍会收到拒绝错误。

**为什么没有通知权限开关？**

WKWebView 不支持网页通知，没有可用的宿主授权接口，做开关也是假开关，所以权限窗口只做说明。

**菜单栏图标看不清 / 颜色不对？**

图标颜色由系统壁纸决定，无法跟随网页变化，这一点与 Plash 相同。

**怎么退出浏览模式？**

三种方式：屏幕子菜单里取消勾选「浏览模式（可交互）」只退出那一块屏；菜单顶层的「退出浏览模式（Esc）」退出全部；直接按 Esc 也退出全部（需要本应用在前台，点一下网页再按即可）。如果浏览模式的窗口盖住了桌面图标或其它窗口，用菜单退出即可，菜单栏始终在窗口之上。

**浏览模式会保留到下次启动吗？**

不会。浏览模式只在本次运行内有效，不写入 `UserDefaults`；重启应用、锁屏或屏幕休眠、手动暂停、显示器布局变化时都会回到纯壁纸。

**网页加载失败怎么办？**

壁纸会显示错误页和原因，可从菜单「全部重新载入」或重新设置网址。请确认网络可用、网址带正确协议和主机名。

**停用某块屏幕后还在占资源吗？**

不会。停用会关闭该屏窗口并卸载网页，`WebContent` 进程随之释放，只显示系统壁纸；重新启用后按该屏网址重新加载。停用状态按显示器 UUID 持久化。

**重启后各屏网址会错位吗？**

不会。每屏网址和停用状态都以显示器 UUID 为键，不依赖屏幕序号或排列顺序。只有在拿不到 UUID 的虚拟显示器上才退化为「名称 + 分辨率」。

## 实现要点

- 壁纸窗口是 `.borderless + .nonactivatingPanel` 的 `NSPanel`，层级为 `CGWindowLevelForKey(.desktopWindow) + 1`，`collectionBehavior` 为 `stationary / canJoinAllSpaces / ignoresCycle`，并设置 `ignoresMouseEvents`，因此不抢焦点、不挡桌面图标
- 进入浏览模式时，该屏窗口去掉 `.nonactivatingPanel`、把层级提到 `NSWindow.Level.normal + 1`、关闭 `ignoresMouseEvents`，并让 `canBecomeKey` / `canBecomeMain` 返回 true，点击页面即可激活应用、获得键盘焦点；退出时逐项还原。浏览状态按显示器 UUID 记录，因此多屏互不影响
- 每块启用的屏幕对应一个 `WKWebView`；空间切换、屏幕唤醒后会重新把窗口置前；显示器参数变化时整体重建
- 使用 `.default()` 网站数据存储，静音媒体可自动播放，元素全屏被关闭；注入脚本隐藏滚动条（macOS 13.3+ 还开启了页面检查器）
- 暂停时用 `takeSnapshot` 截取当前画面顶替网页，随后停止加载并换成空白页；恢复时重新加载
- 网页进程异常终止时会自动重新加载页面（暂停状态下不重载）
- 摄像头 / 麦克风通过 `WKUIDelegate.requestMediaCapturePermissionFor` 拦截；位置通过注入脚本代理 `navigator.geolocation`，用 `WKScriptMessageHandler` 交给 CoreLocation，再用 `window.__wwGeoReply(id, payload)` 把坐标或错误回填页面
- 权限策略存于 `UserDefaults`，询问面板串行展示；面板显示时临时把激活策略切到 `.regular`，结束后恢复 `.accessory`
- Esc 由 `NSEvent.addLocalMonitorForEvents` 统一拦截：只要有任何屏幕在浏览模式，Esc 就退出全部浏览模式并吞掉该按键
